# 观测生活

> 让她知道你此刻在电脑前做什么——只在本机读窗口标题，不截图、不联网、不上传。

一个 [AstrBot](https://github.com/AstrBotDevs/AstrBot) 插件，给角色一双看得见你日常的眼睛。

普通的聊天机器人只在你说话时存在。这个插件让她多知道一点：你从下午三点就坐在同一个窗口前、
刚才那半小时在翻某个文档、已经连着写了两个半小时没起来。

---

## 它看到的东西长什么样

每轮对话前，软件会给模型附上这么一小段（不是你说的，是她"看到"的）：

```
[你此刻的观测｜21:47｜不是他说的，是你看到的。别复述这些数字，别说「我注意到」，自然点用]
正在：VS Code · astrbot_plugin_diary_qzone/main.py
近 30 分钟：写代码 24m、浏览网页 5m
今天：在电脑前 6.4 小时；写代码 3.1 小时、浏览网页 1.7 小时
注意：他已经连续写代码 152 分钟没换过事了。
```

于是她可以自然地接一句「你那个插件还没写完啊」，而不是永远只会问你「今天过得怎么样」。

长时间专注或深夜还在亮着屏幕时，她也可能主动发来一句话——用当前人格的口吻，不报数字、不说教。

## 隐私边界

这个插件会读你的窗口标题，所以边界必须说清楚：

| 做什么 | 不做什么 |
| --- | --- |
| 读前台窗口的**进程名 + 标题** | ❌ 不截图、不录屏 |
| 读键鼠空闲时长（判断人在不在） | ❌ 不记录键击内容、不读剪贴板 |
| 数据写到本机 `data/plugin_data/` | ❌ 不发起任何网络请求，不上传 |
| 超过保留天数自动删除 | ❌ 不读文件内容，不进浏览器历史 |
| 聊天/密码类窗口**只归类不记标题** | ❌ 不采集后台窗口 |

还有几个可随时用的开关：

- `/观测暂停` —— 立刻停手，之后不记录任何窗口
- `/观测清除` —— 删掉今天的记录文件
- 配置里关掉 `enable` —— 完全不采集，也不往对话里注入任何东西

**平台限制**：采集依赖 Windows Win32 API，仅在 Windows 上有效。其他系统会自动跳过，不会报错。

## 安装

```bash
cd AstrBot/data/plugins
git clone https://github.com/baiao218/astrbot_plugin_observe_life.git
```

重启 AstrBot（或在插件页点「重载插件」）。

### 前置条件

- **AstrBot ≥ 4.17.0**
- **Windows**（采集功能）
- 想用主动消息的话，需要知道目标会话的 `unified_msg_origin`，例如 `default:FriendMessage:123456`

---

## 最小配置

```yaml
enable: true                 # 开始采集
inject_enable: true          # 每轮对话告诉她你在做什么
care_enable: true            # 长时间专注/深夜时主动开口
care_umo: ""                 # 填 unified_msg_origin 才会主动发消息，留空则不发
```

其余默认值基本可用。

## 命令

| 命令 | 说明 | 权限 |
| --- | --- | --- |
| `/观测状态` | 采集是否在跑、当前窗口、今日时长分布、最长连续专注 | 管理员 |
| `/观测今天` | 按时间顺序列出今天切换过的窗口（只列 2 分钟以上的） | 管理员 |
| `/观测暂停` | 立刻停止记录 | 管理员 |
| `/观测继续` | 恢复记录 | 管理员 |
| `/观测清除` | 删除今天的记录文件 | 管理员 |

| 键 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `inject_enable` | bool | `true` | 每轮对话附上观测块 |

| 键 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |

| `care_focus_minutes` | int | `90` | 连续专注多少分钟算「该起来了」（只算代码/文档/设计/终端） |

## 它是怎么工作的

```
每 45 秒：GetForegroundWindow → 进程名 + 标题 + GetLastInputInfo 空闲时长
   ↓ append 一行到 2026-10-28.jsonl（纯 append，断电不丢）
读取时合并成连续片段
   ↓ 同窗口且间隔 ≤ 3×采样间隔 → 同一段
   ↓ 空闲超过阈值 → 不计入（看视频/玩游戏豁免）
三个出口：
   ├─ 对话注入：挂在 extra_user_content_parts，不碰 system_prompt
   ├─ 主动关心：专注超时 / 深夜时段 → 用当前人格生成一句话
   └─ today_brief.txt：给 astrbot_plugin_diary_qzone 当作日记素材
```

几个不那么显然的设计：

- **为什么存原始采样而不是实时合并**：写入只是 append，被强杀也不会损坏历史；合并逻辑改进了，
  旧数据照样能用新规则解读。
- **为什么把观测挂在附加块而不是 `system_prompt`**：system prompt 一变，DeepSeek 等模型的前缀缓存
  整段失效，每轮都按全价重算。附加块在末尾，前面仍能命中缓存。
- **为什么看视频不算「走开」**：一集 40 分钟的片子，人会一直不动键鼠。若按空闲硬卡，整段会被判成
  不在电脑前。所以影音和游戏类豁免空闲判定。
- **为什么聊天窗口不记标题**：只归类为「聊天」，不记录具体是哪个对话。聊天软件和资源管理器
  这类窗口出现在记录里没有信息量，反而像被监视。
- **为什么深夜判定要跨午夜**：`23` 点开始的话，深夜是 23:00–05:59 两段拼起来的，
  不是简单的 `hour >= 23`。

## 配合使用

装上 [`astrbot_plugin_diary_qzone`](https://github.com/baiao218/astrbot_plugin_diary_qzone) 之后，
日记会带上今天的底色——「他今天在电脑前待了六个多小时，最长的一次没有停下来，是在写代码」。

两个插件各装各的也能跑；日记插件读不到摘要时会自动跳过，不影响写日记。

## 常见问题

**`/观测状态` 说「他不在电脑前」但我在用**

可能当前窗口在 `IGNORED_APPS` 里（资源管理器、桌面、开始菜单），或者键鼠空闲时间超过了阈值。
也可能是刚才切走了不到一分钟，采样还没抓到。

**看视频时被判成不在**

检查 `idle_timeout` 是不是调得太小。默认 600 秒且影音/游戏类豁免，正常不会误判。

**主动消息一直不发**

`care_umo` 必须填。填了还要满足：不在「刚启动的前两分钟」、今天没超过次数上限、
距离上次超过最小间隔、深夜提醒一晚只发一次。

**换了显示器/多屏会不会乱**

只采前台窗口，跟屏幕数量无关。

**能不能记录手机在干什么**

不能，也不打算做。这个插件只观测这一台 Windows 机器。
